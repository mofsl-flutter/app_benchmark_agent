Section A

Idle CPU and redraw on the watchlist

With nobody touching the phone, the Bench 20 watchlist keeps about two CPU cores busy and redraws about 40 times a second, and half of those frames are identical to the one before. The code shows three sources: every price packet rebuilds a whole row even when the shown numbers did not change, the header wealth tile rebuilds on every holdings tick and animates every 3 s, and new tick streams are created on every build. These changes keep every price, colour and animation the user sees, but stop the work that draws the same pixels again.

A2

Rebuild a row only when its shown values change

Each price packet rebuilds the whole row, even when the packet only changed a field the row does not show. Pass a packet to the row only when the text it displays would change, and keep the static left column out of the tick builder.

Teams FERisk MediumEffort M · 2–4 daysNo visible changeverify on deviceDepends on A1 A3

Today

The StreamBuilder wraps the row's whole Column: name, exchange badge, MTF chip, the animated 'Updates' chip, SVG arrow, CasSessionRow, performance and P&L lines. The broadcaster keeps one BroadcastResponse2 per symbol, mutates it in place and re-publishes it for every packet (mosl_broadcaster broadcast_channel.dart 243-251), so every packet for a symbol rebuilds the whole row, including packets that change only volume, OI or depth when the row shows LTP and change. These rebuilds draw the same pixels, which matches the 49.5 % identical idle frames (verify the share with the DevTools rebuild counter).

What to change

  1. Add String _shownKey(BroadcastResponse2 t): ltpValue, changeValue, perChangeValue and the sign of change; plus bid/ask/high/low/volume strings when isDetailedView; plus casRefPrice, inductiveEquilibriumPrice, inductiveEquilibriumQty, imbalanceQuantity, imbalanceQuantityFromMktOrder (CasSessionRow and the CAS view read these); plus ltp when holdings or performance lines are shown.
  2. Because the same object is mutated in place, compare against the last key string, not the last object (Stream.distinct on the object would never fire).
  3. In initState and didUpdateWidget (when streamCtrl changes) build _filtered = widget.streamCtrl.where((t) { final k = _shownKey(t); if (k == _lastKey) return false; _lastKey = k; return true; }). Use it only when WatchlistPerfFlags.rowTickDiff is true.
  4. Move the left Flexible (name, badges, MTF, Updates chip) out of the builder so it is built once per row build, and keep only rightColumnLtp and the lower lines inside the StreamBuilder.
  5. Reset _lastKey when isDetailedView, showPerformance or isCasScrip change.

A3

Reuse one tick stream per row

The listing creates a new filtered stream for every row on every build, so each row's StreamBuilder unsubscribes, resubscribes and replays the cached tick. Cache one stream per symbol in the listing state.

Teams FERisk LowEffort S · ≤ 1 dayNo visible change

Today

onTickReceived builds helper.onStreamReceived().where(...).startWith(cached) each time it is called (trader_widgets StreamingBaseWidget.dart 54-59). It is called inside itemBuilder, so every list build hands each WatchlistItem a different Stream; StreamBuilder treats that as a new stream, cancels, resubscribes and immediately rebuilds with the cached value.

What to change

  1. Add final Map<BroadcastSymbol, Stream<BroadcastResponse2>> _tickStreams = {} to _WatchlistListingState.

  3. In didUpdateWidget, drop entries for symbols no longer in watchistScrips.

A5

Rotate the wealth tile less, or not on the watchlist

The wealth tile flips between MO Wealth and External Wealth every 3 s with a 500 ms animation, for as long as the header is mounted. Add an optional rotation interval and an opt-out to the shared widget, defaulting to today's 3 s, and let the landing header pass a slower value on the Watchlist tab once Product agrees.

Teams FE · sharedProductRisk MediumEffort S · ≤ 1 dayVisible to usersverify on device

Today

_startAutoScroll starts Timer.periodic(3 s) and each tick calls animateToPage over 500 ms. There is no check for which tab is showing. On a 120 Hz display a 500 ms animation every 3 s is about 60 frames per 3 s, roughly 20 fps on average, which is about half of the 39.6 idle fps measured (verify by turning it off on a test build).

What to change

  1. Add final Duration autoRotateEvery to WealthOverviewTile and _WealthOverviewTileContent, default Duration(seconds: 3).
  2. In _startAutoScroll, return without a timer when autoRotateEvery == Duration.zero or tiles.length < 2; otherwise use autoRotateEvery.
  3. In landingpage_header.dart, when widget.bottomBarName is the Watchlist tab, pass the Remote Config value; default 3 s keeps today's behaviour.

A7

Profile the remaining idle CPU before and after

Part of the 185.5 % CPU cannot be attributed from the code alone: socket packet parsing on the UI isolate, the texture compositing pass (C5) and the rise from 110.5 % to ~187 % between sessions. Capture a CPU profile of one idle minute before and after A2–A6 and C1.

Today

handleSocketData parses every socket packet on the main isolate (dataMapper.map) and publishes each QuoteResponse. C1 rose from 110.5 % in the 10-min first session to 185.5 % and 188.7 % later; the code does not tell whether that is market activity or accumulated listeners (B1, B5).

What to change

  3. Repeat after A2–A6 and C1; repeat a 10-min session to see whether CPU still rises over time.
  4. If parsing dominates, raise moving parsing to a background isolate with the mosl_broadcaster owners (separate change).
