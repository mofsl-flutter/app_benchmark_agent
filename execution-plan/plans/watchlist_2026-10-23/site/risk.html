High-risk changes (4)

Each of these ships behind a flag, gets a full regression pass, and is released on its own.

IDChangeWhy it is high riskHow it is kept safe
C5Test SurfaceView rendering on Android 11+
FE · sharedBE		App shell change for every screen. The code comment says surface mode was 'crash-prone' on Android 10 and below, and platform views (WebView charts, payment SDKs) behave differently between modes. Must ship behind a flag, default texture, with a full regression pass.
  • Default false keeps texture mode for everyone.
  • Takes effect on the next cold start only, never mid-session.
  • Rollback is a Remote Config change plus one relaunch.
E3Restart the connectivity listener after background
FE · shared		Shared base class of every streaming screen. The fix makes toggleIsInterNetAvailable fire again after a resume, which today silently stops; screens that reload on reconnect will start doing so again. Ship behind a flag and run a regression pass on the main streaming screens.
  • Behind a Remote Config flag, default off (today's behaviour).
  • No change for screens that never go to background.
H1Quick-action sheet over the watchlist
FEProduct		New user-facing flow on the main list and a possible change to an existing gesture (long-press opens edit mode today). Needs live depth subscription and order-entry navigation. Behind WatchlistPerfFlags.quickActions, default off, with a full regression pass on the list.
  • Behind WatchlistPerfFlags.quickActions, default off.
  • Tap-to-quote and swipe-to-trade unchanged.
  • Order placement goes through the existing order form, not a new path.
H2Intraday sparkline on watchlist rows
FEBEProduct		New data source and new painting on every row; can undo the idle and scroll gains if not done carefully (one CustomPainter per row with shouldRepaint on data change only, RepaintBoundary). Behind a flag.
  • Behind a flag (add a key to A1's holder), default off.
  • Painter repaints only on series change.
