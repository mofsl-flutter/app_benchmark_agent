1. Main problems found

The problems behind most of the slowness, heaviness and instability, in order of impact.

Problem and causeEffect todayFixed by
Live ticks rebuild things that look the same
Every price packet rebuilds a whole watchlist row, even when it changed only fields the row does not show; the header wealth tile rebuilds twice per holdings tick; new tick streams are created on every build of the list and the indices rail.		185.5 % CPU on an idle Bench 20 list (C1) and 49.5 % of idle frames identical to the previous one (U5).A2 A3 A4 A6 A7
The header wealth tile animates every 3 seconds
MO Wealth / External Wealth flip with a 500 ms page animation every 3 s for as long as the header is mounted, which is always on the watchlist.		About 60 frames every 3 s, roughly half of the 39.6 fps idle redraw (U4, verify); also the header shift users notice.A5 J5
Scrolling down rebuilds the whole header every frame
The list emits a new header-pin state on every scroll update and the header BlocBuilder rebuilds the landing header, indices rail, tab bar and banners each time; the whole screen also rebuilds on each list update; the app renders through a texture view on Android 11+.		75.3 fps while scrolling on a 120 Hz screen, about 63 % of offered frames, although jank is only 0.34 % (S5, S1).C1 C2 C3 C4 C5
Rows are recreated on every update and leak listeners
Keys are created in build, so every list update unmounts and remounts every row; each row leaves a stream subscription and three tooltip controllers behind; the cubit is app-scoped, so leftovers live for the session.		+60.0 MB over 10 open/close cycles (R9) and 380.5 MB after 5 min (R3).B1 B2 B3 B4 B5 B6 B7
Offline and stale prices look live
The only offline message is gated on a bottom-bar index the RISE shell does not appear to set; rows use the same style online and offline; the connectivity listener stops after the first background.		Offline score 44.4 (O1): no banner, no last-updated marker, stale prices after a return from background (U3).E1 E2 E3 D2
Release builds write user data and noise to logcat
CleverTap events are printed with print; every cached response is printed; an 'API Failed' line is written before every response; the logged URL doubles the origin; the committed HEAD still prints the bearer token.		Client code, holdings data and misleading errors in release logcat (creation notes); extra string conversions on every API call.F1 F2 F3 F4 F5 F6 F7 F9
