Section E

Offline and reconnect

When the network drops, the watchlist keeps its prices on screen (good) but gives no sign that they are old: no banner, no timestamp, and the prices look exactly like live ones. The only offline message in the code is a snackbar that is gated on a bottom-bar index the RISE shell does not seem to set. An offline cold start stops at the mPIN screen with a generic error. These changes add an in-screen offline banner and a stale marker behind flags, fix a listener that stops after the first trip to the background, and put the cold-start question to Product.

E1

Show an offline banner on the watchlist

The watchlist's offline message is a global snackbar that only shows when BottomNavCubit.currentPageInd == 1, and the RISE shell that hosts the watchlist does not appear to set that index. Add a small in-screen banner above the list, driven by the connectivity events the screen already receives, behind a flag.

Teams FEProductRisk MediumEffort S · ≤ 1 dayVisible to usersverify on deviceDepends on A1 E3

Today

toggleIsInterNetAvailable(false) calls showNoInternetToast() only when cubit.shouldShowToast is true, which requires MyNavigatorObserver.instance.isLandingPageVisible and BottomNavCubit.currentPageInd == 1. currentPageInd is assigned only in trader_bottom_bar/lib/bottom_navigation.dart (lines 566 and 598); the RISE dashboard hosts the watchlist from mo_dashboard/lib/dashboard_screen.dart line 263 and does not assign it (verify on device by logging the value).   3. Do not change shouldShowToast; the snackbar path stays as today.
  4. Log BottomNavCubit.currentPageInd once in a debug build on the RISE shell to confirm the gating cause.

E2

Mark prices as not live when offline or reconnecting

Offline or right after a return from background, rows show the last cached price in the same style as live prices. While the price socket is not logged in, dim the LTP and show 'Last updated hh:mm:ss' under the list, behind a flag.

Teams FEProductRisk MediumEffort M · 2–4 daysVisible to usersDepends on A1

Today

rightColumnLtp renders bdData.ltpValue with surfaceTextNeutralNormal and the change in red/green regardless of connection state. The socket state is available as BroadCastHelper.instance.socketStateStream and is already shown as a small coloured dot by BroadcasterInteractiveIndicator in the landing header, which users do not read as 'stale'. After a 60 s absence the socket is closed (see D2), so the same live-looking style also covers the reconnect period measured in U3.

What to change

  1. In the listing state, subscribe once to socketStateStream; isLive = state == SocketState.loggedIn; remember the time of the last received tick (update from any row tick or from the quote stream).
  2. Pass isLive into WatchlistItem; in rightColumnLtp, when !isLive and the flag is on, use context.surfaceTextNeutralDisabled (DSM token) for both lines.
  3. Under the list header show 'Last updated <time>' while !isLive.
  4. Debounce the not-live state by 2 s so normal reconnects do not flash.

E3

Restart the connectivity listener after background

StreamingBaseWidget cancels its connectivity subscription when the app is paused but keeps the cancelled object, and only subscribes again when the field is null. After the first trip to the background, streaming screens (the watchlist included) stop receiving offline/online events. Set the field to null after cancelling.

Teams FE · sharedRisk HighEffort S · ≤ 1 dayVisible to usersverify on device

Today

didChangeAppLifecycleState(paused) calls stopNetworkStreaming(), which does subscription?.cancel() but leaves subscription non-null. On resume, startNetworkStreaming() runs subscription = subscription ?? AppEventStreamImpl...listen(...), so the cancelled subscription is kept and no new listener is attached. From then on toggleIsInterNetAvailable is never called for that screen (verify on device: background once, then toggle airplane mode and log the callback).

What to change

  1. Add a static flag in trader_widgets read from Remote Config (default false).
  2. In stopNetworkStreaming: subscription?.cancel(); if (flag) subscription = null;
  3. Regression: watchlist, quote page, positions, holdings, option chain: background, return, airplane on/off.

E4

Decide whether an offline start may show cached data

An offline cold start lands on the mPIN screen with 'Oops, something went wrong! Please try again later.' and never reaches the watchlist, although the watchlist responses are cached on disk (fetchWatchlist uses isForcedCacheEnable). Whether a cached, read-only watchlist may be shown before the mPIN is validated online is a Product and security decision.

Teams ProductBERisk LowEffort S · ≤ 1 dayVisible to users

Today

The benchmark recorded the mPIN screen with a generic error on an offline cold start and no way to reach the watchlist. In the watchlist module, fetchWatchlist and fetchWatchlistById already request isForcedCacheEnable with a cache callback (watchlist_repository_impl.dart 17-24, 132-142), so cached lists exist; the blocker is the login flow (mo_login_unified), which this plan did not analyse line by line.

What to change

  1. Product decides (1) and (2).
  2. If (1): small change in the login package to map the offline error to the existing 'Please check your internet connection.' message (trader_network exceptions.dart already returns it when offline).
  3. If (2): separate design and security review before any code.
